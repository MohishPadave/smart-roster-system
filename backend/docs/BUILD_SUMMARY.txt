🔧 TECHNICAL IMPLEMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Database Schema (apps/web/prisma/schema.prisma):
  • Pod - Team grouping with self-referential podLeadId
  • Employee - DEDICATED/SHARED/FLOAT_BACKUP with processSkillTags
  • Brand - D2C brand with accountTier
  • BrandProcessRule - CS/ACC/NDR/RETENTION, ALL_365/EXCL_PH/EXCL_SUN_PH
  • EmployeeAllocation - PRIMARY/SECONDARY_BACKUP with allocationWeight
  • LeaveRequest - APPROVED_LEAVE/COMP_OFF with status tracking
  • HolidayCalendar - Public holidays with unique date constraint
  • RosterVersion - Monthly roster container with DRAFT/PUBLISHED status
  • ShiftEntry - Daily assignments with W/WO/PH/AL/CO/BK codes

Seed Data (apps/web/prisma/seed.ts):
  • 3 Pods (Alpha, Beta, Gamma) with designated leads
  • 35 Employees across roles with varied skills and preferences
  • 22 D2C Brands (18 single + 4 multi-resource, 80/20 split)
  • PRIMARY (1.0 FTE) + SECONDARY_BACKUP allocations
  • 2 Public Holidays (Nov 1, Nov 15, 2026)
  • 11 Pre-approved Leaves (AL + CO)
  • Intentional SPOF risks for testing

CP-SAT Solver (apps/solver-service/app/engine/solver.py):
  • HARD P0: Coverage (>= minHeadcount), Leave Lock, Capacity Cap, Skill Match
  • HARD P1: Weekly Offs (>= 4), Max Consecutive (≤ 6 days)
  • SOFT: Brand Continuity (W=10), Preferred WO (W=6), Equitable Sundays (W=4)
  • Infeasibility Diagnostics: Unsatisfiable core + remediation hints
  • Deterministic: Same inputs → same outputs

Reoptimizer (apps/solver-service/app/engine/reoptimizer.py):
  • Freezes past dates (< disruptionDate)
  • Locks unaffected employees' schedules
  • Marks disrupted employees as AL
  • Ranks backup candidates by: certification, utilization, fatigue
  • Outputs cascade diff (before/after visual)
  • Minimizes perturbation count (Hamming distance)

SPOF Audit (apps/solver-service/app/engine/spof.py):
  • Flags brands with zero backup on critical dates
  • Checks only operating days (respects EXCL_SUN_PH, EXCL_PH)
  • Risk levels: HIGH (>2 dates), MEDIUM (≤2 dates)
  • Returns affected dates and plain-English descriptions

FastAPI Routes (apps/solver-service/app/main.py):
  • GET  /health          - Health check
  • POST /solve           - Generate monthly roster
  • POST /reoptimize      - Handle mid-month disruptions
  • POST /audit/spof      - Pre-flight Bus Factor audit

📋 KEY DESIGN DECISIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Monorepo Structure
   • Separates web app (Next.js) and solver service (Python)
   • Enables independent scaling and deployment
   • Clear separation of concerns (UI vs. optimization engine)

2. Prisma + PostgreSQL
   • Type-safe database access with generated client
   • Migration support for schema evolution
   • Prisma Studio for visual data inspection

3. Google OR-Tools CP-SAT
   • Industry-standard constraint programming solver
   • Deterministic results (reproducible)
   • Handles both hard and soft constraints
   • Efficient for 30-day x 35-employee scale

4. Infeasibility Diagnostics
   • Returns actionable remediation hints (not just "infeasible")
   • Groups conflicting constraints by type
   • Helps users understand why roster generation failed

5. Minimal-Perturbation Reoptimization
   • Freezes past dates (stability)
   • Minimizes changes to existing schedules (employee satisfaction)
   • Ranks backup candidates objectively (certification + utilization + fatigue)

6. SPOF Audit Pre-Flight
   • Proactive risk detection before roster generation
   • Identifies brands lacking backup coverage
   • Guides hiring/training decisions

7. Seed Data Design
   • Intentional SPOF risks for testing radar functionality
   • Mathematically feasible scenario (passes all constraints)
   • 80/20 split (single vs. multi-resource brands) mirrors real operations
